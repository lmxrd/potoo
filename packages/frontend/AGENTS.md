# AGENTS.md

The dashboard: a client-rendered React SPA (Vite, Tailwind CSS 4, TanStack
Router and Query, shadcn/ui), embedded in the backend's binary. The root
AGENTS.md has the rules of the whole repository; these are the frontend's.

## Commands

Run them through mise from the repository root (`mise run check:frontend`,
`test:frontend`, `dev:frontend`): those regenerate the SDK first. Inside this
folder:

- `pnpm dev` — dev server at http://localhost:5173 (`/api` goes to :8000)
- `pnpm build` — production build into `dist/`
- `pnpm test` — the Vitest unit tests
- `pnpm check` — oxfmt --check, oxlint and tsc (read-only; must pass)
- `pnpm fix` — oxfmt and oxlint --fix

## Dependencies

- Prefer a well-known, maintained package over writing the same thing
  ourselves. Propose it first (name, exact version, why) and get approval
  before adding it, then add it at that exact version. Write it ourselves
  only when no maintained one fits, and say why in a comment where it lives.
- The workspace refuses versions less than a day old (`minimumReleaseAge`
  in the root `pnpm-workspace.yaml`): take the newest that is older.

## Conventions

- **API:** only through the generated SDK (`potoo-sdk`, `packages/sdk`, not
  committed): its TanStack Query options and mutations
  (`potoo-sdk/react-query`) and types (`potoo-sdk/types`), through the one
  `queryClient` (`src/lib/query-client.ts`). A mutation whose component
  shows its own error (with `errorMessage`, `src/lib/api.ts`) passes
  `meta: { inline: true }`; any other failed mutation shows a toast
  (sonner). A 401 outside `/api/auth/*` means the session ended: the app
  goes to `/login` (`setSessionExpiredHandler` in `src/main.tsx`). The one exception is the single
  sign-on button, a plain link to `/api/auth/oidc/login`. Ids are opaque
  strings (UUIDv7): never parse or compare them as numbers.
- **Files:** names under `src/components/` and `src/lib/` are kebab-case
  (`two-factor-section.tsx`, `date-range.ts`); the exported component or
  hook keeps its own name (`TwoFactorSection`). Components are grouped by
  feature: `auth/` (sign-in and setup forms), `stats/` (the dashboard),
  `settings/` (the user's own settings), `admin/` (the admin settings),
  `common/` (shared by several: `confirm-dialog.tsx`, `error-text.tsx`) and
  `ui/` (shadcn/ui). `src/routes/` keeps TanStack Router's file-route names.
- **Routing:** file-based TanStack Router, one file per route in
  `src/routes/`; `src/routeTree.gen.ts` is generated by the Vite plugin and
  committed — never edit it by hand.
- **Settings:** `settings.tsx` is the layout (the side menu of
  `components/settings/settings-layout.tsx` and an `<Outlet />`), one route
  per page: `settings.account.tsx`, `settings.appearance.tsx`,
  `settings.password.tsx` (`/settings` goes to the account); the admin pages
  are under `settings.admin.tsx`, which sends anyone but an admin back to
  their account (`settings.admin.users.tsx`, `settings.admin.sso.tsx`). A
  new page gets its route and a link in the layout.
- **UI:** shadcn/ui components in `src/components/ui`, the `base-vega` style
  (Base UI primitives, `@base-ui/react`, styled with Tailwind; lucide-react
  for icons). Use them rather than plain elements: `Button`, `Input`, `Checkbox`, `Select`, `Card`, `Table`,
  `DropdownMenu`, `Dialog`; ask for a confirmation with `useConfirm`
  (`src/components/common/confirm-dialog.tsx`, an AlertDialog), never `window.confirm`.
  They are ours to edit (shadcn copies the source in), but keep changes in
  the component, not at the call sites.
- **Base UI, not Radix:** there is no `asChild`; render a component as
  another element with `render`
  (`<DropdownMenuItem render={<Link to="/settings" />}>`,
  `<Button nativeButton={false} render={<a href={url} />}>`). Menu items take
  `onClick` (no `onSelect`). A `Select` shows its value's label only when it
  gets `items` (`{ value, label }[]`), and `onValueChange` can pass `null`.
  State is in data attributes (`data-open`, `data-closed`, `data-checked`,
  `data-highlighted`, `data-disabled`), styled as `data-open:...`.
- **Theme:** colours only through the semantic tokens of `src/index.css`
  (`bg-background`, `text-foreground`, `bg-primary`, `text-muted-foreground`,
  `border-border`, ... plus potoo's `text-soft-foreground`, `fill-faint`,
  `text-success`), never hard-coded, so a theme switch shows at once. A
  theme is a base (light/dark, `data-theme` on the root, which also drives
  `dark:`) and an accent (`--accent-color` and `--on-accent-color`, set by
  `applyTheme` in `src/lib/themes.ts`); `--primary` is the accent and
  `--accent` (shadcn's) a wash of it for hovers.
- **Dates and times:** show them with `useFormatters()`
  (`src/lib/use-formatters.ts`), bound to the signed-in user's date format
  and clock; the pure functions under it are in `src/lib/dates.ts`. Do not
  pass the user's `date_format` or `use_24` down as props to format with.
- **Duplicated lists:** the date formats (`src/lib/dates.ts`) and the single
  sign-on error codes (`src/routes/login.tsx`) are listed in the backend
  too: change both.
- **Tests:** Vitest, for the pure logic in `src/lib` (colocated
  `*.test.ts`, node environment). No component or snapshot tests.
- TypeScript strict: unused imports and locals fail the check.

## Imports

- Use relative imports (`../lib/api`, `./button`); there is no `@/` alias in
  the app or the bundler, and no file in `src/` imports from `@/`.
- The API client comes from the `potoo-sdk` workspace package
  (`packages/sdk`), by its entry points: `potoo-sdk` (the types and the
  generated functions), `potoo-sdk/react-query` (query options and
  mutations), `potoo-sdk/types` and `potoo-sdk/client`.
- `tsconfig.json` keeps a `paths` entry for `@/*` only so the shadcn CLI can
  resolve its targets. After `pnpm dlx shadcn@latest add <name>`
  (`components.json`), rewrite the generated `@/lib/utils` and
  `@/components/ui/*` imports to relative paths (`../../lib/utils`,
  `./button`). The base-vega registry (as of shadcn 4.23) imports `cn` from
  a package `"cn"` and lists `cn` as a dependency: never install it, look at
  the file first (`add <name> --dry-run --view`) and import `cn` from
  `../../lib/utils`.
