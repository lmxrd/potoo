# AGENTS.md

The dashboard: a client-rendered React SPA (Vite, Tailwind CSS 4, TanStack
Router and Query, shadcn/ui), embedded in the backend's binary. The root
AGENTS.md has the rules of the whole repository; these are the frontend's.

## Commands

Run them through mise from the repository root (`mise run check:frontend`,
`test:frontend`, `dev:frontend`): those regenerate the SDK first. Inside this
folder:

- `pnpm dev` — dev server at http://localhost:5173 (`/api` goes to :8000)
- `pnpm build` — production build into `dist/`
- `pnpm test` — the Vitest unit tests
- `pnpm check` — oxfmt --check, oxlint and tsc (read-only; must pass)
- `pnpm fix` — oxfmt and oxlint --fix

## Dependencies

- Prefer a well-known, maintained package over writing the same thing
  ourselves. Propose it first (name, version, why) and add it only once it
  is approved. The workspace refuses versions less than a day old
  (`minimumReleaseAge` in the root `pnpm-workspace.yaml`): take the newest
  that is older.

## Conventions

- **API:** only through the generated SDK (`potoo-sdk`, `packages/sdk`, not
  committed): its TanStack Query options and mutations
  (`potoo-sdk/react-query`) and types (`potoo-sdk/types`); errors are shown
  with `errorMessage` (`src/lib/api.ts`). The one exception is the single
  sign-on button, a plain link to `/api/auth/oidc/login`. Ids are opaque
  strings (UUIDv7): never parse or compare them as numbers.
- **Routing:** file-based TanStack Router, one file per route in
  `src/routes/`; `src/routeTree.gen.ts` is generated by the Vite plugin and
  committed — never edit it by hand.
- **UI:** shadcn/ui components in `src/components/ui` (Radix primitives,
  styled with Tailwind; lucide-react for icons). Use them rather than plain
  elements: `Button`, `Input`, `Checkbox`, `Select`, `Card`, `Table`,
  `DropdownMenu`, `Dialog`; ask for a confirmation with `useConfirm`
  (`src/components/confirm.tsx`, an AlertDialog), never `window.confirm`.
  They are ours to edit (shadcn copies the source in), but keep changes in
  the component, not at the call sites.
- **Adding a shadcn component:** `pnpm dlx shadcn@latest add <name>`
  (`components.json`), then rewrite its `@/lib/utils` and
  `@/components/ui/*` imports to relative paths (`../../lib/utils`,
  `./button`): there is no `@/` alias in the bundler; `tsconfig.json` has
  the path only so the CLI can resolve its targets.
- **Theme:** colours only through the semantic tokens of `src/index.css`
  (`bg-background`, `text-foreground`, `bg-primary`, `text-muted-foreground`,
  `border-border`, ... plus potoo's `text-soft-foreground`, `fill-faint`,
  `text-success`), never hard-coded, so a theme switch shows at once. A
  theme is a base (light/dark, `data-theme` on the root, which also drives
  `dark:`) and an accent (`--accent-color` and `--on-accent-color`, set by
  `applyTheme` in `src/lib/theme.ts`); `--primary` is the accent and
  `--accent` (shadcn's) a wash of it for hovers.
- **Duplicated lists:** the date formats (`src/lib/dates.ts`) and the single
  sign-on error codes (`src/routes/login.tsx`) are listed in the backend
  too: change both.
- **Tests:** Vitest, for the pure logic in `src/lib` (colocated
  `*.test.ts`, node environment). No component or snapshot tests.
- TypeScript strict: unused imports and locals fail the check.
